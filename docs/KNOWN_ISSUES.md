# Known Issues — SHOHAN CV STUDIO 1.0.0

Severity: **S1** blocks a core task · **S2** degrades quality · **S3** cosmetic
or inconvenience.

Every item below is a real, observed property of this build. Nothing is listed as
"known" merely because it was not examined; conversely, the *absence* of an item
does not mean the area was verified on Windows — see
[COMPATIBILITY.md](COMPATIBILITY.md).

---

## Platform and packaging

| # | Sev | Issue | Workaround |
| --- | --- | --- | --- |
| 1 | **S1** | **No installation on any Windows version has been verified.** The installer configuration is committed and reviewable, but building the executables requires downloading the Electron runtime, which was blocked in this environment. | Build with `npm run dist:win` on a machine with internet access, then run the manual checklist in [TESTING.md](TESTING.md#manual-smoke-checklist) before distributing. |
| 2 | **S1** | **Printing and PDF generation were not exercised.** No printer, spooler or Electron runtime was available. | Print once from *Print preview* on the target PC before relying on it; test PDF export first because it is the least device-dependent path. |
| 3 | S2 | **Unsigned executables trigger SmartScreen** on Windows 10/11. | Sign the build (`CSC_LINK` / `CSC_KEY_PASSWORD`) or instruct users to use *More info → Run anyway*. |
| 4 | S2 | Windows 7 SP1 additionally needs KB4474419 (SHA-2 signing support) and an updated root certificate store for signed binaries. | Apply Windows Update, or distribute the portable build. |
| 5 | S3 | No auto-update mechanism (deliberate: the product is offline-first). | Distribute new installers; user data is preserved across upgrades. |

## Rendering

| # | Sev | Issue | Workaround |
| --- | --- | --- | --- |
| 6 | S2 | **Printing depends on the driver honouring A4 and "no scaling".** Some drivers apply their own fit-to-page and shrink margins. | Set Paper = A4 and Scale = 100 % in the printer dialog, or print to PDF first. |
| 7 | S2 | A very small number of specialist fonts substitute the bundled ones in Word, which can shift Bengali conjunct positions in DOCX. | Use Word 2010 or newer; the DOCX declares Noto Sans Bengali / Noto Serif Bengali explicitly. |
| 8 | S3 | On displays with non-integer scaling (125 %, 175 %) the preview can show a half-pixel hairline on section rules. | Cosmetic only; does not appear in print or PDF, which are millimetre-based. |

## Functional

| # | Sev | Issue | Workaround |
| --- | --- | --- | --- |
| 9 | S2 | **The database is held in memory and rewritten whole on change** (sql.js). Opening a database with thousands of projects takes noticeably longer. | Measured fine for normal use (hundreds of CVs). Archive old projects and restore from backup if the file grows beyond a few hundred MB. |
| 10 | S2 | Two application instances pointed at the same data folder can overwrite each other's last write (no file lock — Electron 22 has no cross-process lock API used here). | Run one instance per Windows user; the database lives in that user's profile. |
| 11 | S3 | Editing the *same project* in two windows is not supported. | Use one editor window; duplicate the project for parallel work. |
| 12 | S3 | Custom sections always render as body text with a heading; they cannot use the timeline layout. | Use an existing timeline section (e.g. Projects) instead, or split the content into shorter custom sections. |
| 13 | S3 | Portrait images are stored inside the project; very large photos (several MB) increase the database and backup size. | Use an image up to ~1000 px on the long edge; the app downscales on import. |

## Privacy and data

| # | Sev | Issue | Workaround |
| --- | --- | --- | --- |
| 14 | S3 | Backups are **not encrypted** — anyone with the ZIP can read the CV data. | Store backups on encrypted media or in an encrypted container; the archive is a standard ZIP by design so it stays recoverable in ten years. |
| 15 | S3 | *Delete all data* permanently removes projects, customers and history; it cannot be undone from inside the app. | Create a backup first — the confirmation dialog reminds you. |

## Documentation and previews

| # | Sev | Issue | Workaround |
| --- | --- | --- | --- |
| 16 | S3 | The PNG previews in `docs/images` are generated by a Python preview renderer (Pillow + HarfBuzz + FreeType) that reproduces the production geometry, not by Chromium itself. They are faithful but not pixel-identical to the app. | Treat them as design references; the definitive output is the app's own preview/PDF. |
| 17 | S3 | Regenerating previews needs Python packages (`pillow`, `fonttools`, `brotli`, `uharfbuzz`, `freetype-py`). | Only needed for maintainers; the committed images are enough for users. |

## Not issues (behaviour by design)

* Optional sections that are empty or switched off produce **nothing** — no
  heading, no rule, no blank page. This is the required behaviour.
* Sensitive fields (NID, passport, religion, marital status, blood group, date of
  birth, photo) are excluded from output until explicitly enabled.
* There is no account, no cloud sync, no telemetry and no network traffic of any
  kind.
* Multi-page CVs are expected; the app never squeezes content onto one page.
* ATS templates contain no skill bars, icons or photo.

## Reporting a problem

Include: Windows version and build, whether the installer or portable build was
used, the exact action, what happened, what was expected, and the contents of
*Help → Diagnostics* (or `%APPDATA%\Shohan CV Studio\data\shohan-desktop.log`).
